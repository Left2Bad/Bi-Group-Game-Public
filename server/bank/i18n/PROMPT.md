# Задача для ИИ-агента с доступом к проекту: улучшить перевод банка вопросов

Скопируйте блок «Промпт» ниже целиком в агента, открытого в корне проекта. Укажите язык: `kk`, `en` или оба.

---

## Промпт

Ты редактор-переводчик, носитель языка, специалист по строительной отрасли. Работаешь в репозитории BI Academy (тест для сотрудников строительной компании, Казахстан).

**Задача.** Банк из 300 рабочих ситуаций уже переведён с русского на казахский и английский. Перепроверь и улучши перевод **{kk | en | оба языка}**, исправляя файлы на месте.

**Где что лежит**
- Русские оригиналы: `server/bank/field.json`, `server/bank/engineering.json`, `server/bank/operations.json` (поля `question.context`, `question.text`, `question.options[].text`) и вопросы `Q01–Q15` в `src/content/questions.ts` (`situations`).
- Переводы: `server/bank/i18n/kk/01.json … 10.json` и `server/bank/i18n/en/01.json … 10.json`.
  Формат: `{ "<ID вопроса>": { "context": "...", "text": "...", "options": { "<ID варианта>": "..." } } }`.
  ID вариантов в банке — `A`–`D` (для `FIELD_*`, `ENG_*`, `OPS_*`) и `Q01-A`…`Q15-D` (для `Q*`). Сверяйся с оригиналами, не угадывай.
- Все остальные файлы проекта **не трогай**: ни код, ни русские оригиналы, ни `src/i18n/*` (интерфейс переводит другой человек).

**Как работать**
1. Прочитай этот файл и `docs/question-bank.md` (контекст методики). Не меняй смысл вопросов и баллы.
2. Иди по файлам `01.json … 10.json` по очереди. Для каждого вопроса сравни перевод с русским оригиналом и исправь:
   неточный смысл, потерянный оттенок («объясню» ≠ «потребую», «предложу» ≠ «сам решу», «согласую» ≠ «оформлю»), грамматику, кальки и канцелярит.
   Если перевод хороший — оставь как есть, не переписывай ради переписывания.
3. После каждого файла запускай `npx vitest run server/content-translations.test.ts`. Он проверяет, что у каждого из 300 вопросов есть полный перевод
   (context, text и все 4 варианта) и что в английском нет кириллицы. Тест должен проходить всегда.
4. В конце составь короткий отчёт: сколько вопросов исправлено по каждому языку, список спорных терминов для носителя, что не смог решить.
5. Ничего не коммить без отдельной просьбы.

**Жёсткие правила**
- Не меняй ключи, ID вопросов и вариантов, структуру JSON, количество вариантов (всегда 4), порядок вариантов.
- Варианты ответов должны остаться РАВНОЦЕННЫМИ: не делай ни один вариант «правильнее», мягче или резче оригинала. Это психометрический тест, правильного ответа нет.
- Текст от первого лица сотрудника («Сверю…», «Попрошу…»), нейтральный деловой тон. Вопрос «Какой подход в этой ситуации вам ближе?» переводи единообразно во всех вопросах.
- Числа, единицы, проценты и аббревиатуры (ППР, ПТО, ВК, ОВиК, ЭОМ, BIM, BIG Engineering, BuildEX, BIU) сохраняй.
- Пиши как живой инженер или прораб, не калькой с русского. Избегай повторов («рәсімдеймін … рәсім бойынша»).
- Один и тот же термин переводи одинаково во всех 300 вопросах (глоссарий ниже). Если меняешь термин, меняй его везде.
- Валидный JSON, UTF-8, отступы как в текущих файлах.

**Глоссарий** (если не уверен, выбери лучший вариант и применяй везде; спорное внеси в отчёт)

**Известные ошибки — найди и исправь, не повторяй**
- kk: «Бөлуден кейін» (после разделения) вместо «после разбивки» (`ENG_053`).
- kk: «Жоспарлаудың өзгеруі» (изменение планирования) вместо «изменение планировки» (`OPS_052`).
- kk: «Жабықты сақтап» неясно; нужно «проход оставлю закрытым» (`OPS_012`).
- kk: «Бригаданы жібермеймін» (не отправлю) вместо «не допущу к работе» (`OPS_008`).
- kk: «Файлдарды бірыңғай атауды ұсынып» — грамматика; нужно «файлдарға бірыңғай атау беруді ұсынып» (`ENG_057`).
- kk: слишком буквальные «ескерту ашық тұр», «жанасу түйіні», «ревизиясындағы», «өткізіп алу», «рәсімдеймін … рәсім бойынша».
- en: «put into work» → «released for use / put into service»; «it is not described how…» → «there is no description of how…»;
  громоздкое «a batch … that is planned to be issued» → «a batch … due to be issued».
  Это примеры из выборки; пройди и остальные вопросы тем же критерием.

**Самопроверка в конце**
1. `npx vitest run server/content-translations.test.ts server/question-bank.test.ts` проходит.
2. `git diff --stat` затрагивает только `server/bank/i18n/**`.
3. В английских файлах нет кириллицы, в казахских нет оставшихся русских слов (кроме принятых аббревиатур).
