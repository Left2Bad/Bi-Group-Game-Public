# Банк готовых вопросов

Первые 10 ситуаций теста ИИ **выбирает из таблицы `question_bank`**. Сервер предварительно отбирает до 80 активных кандидатов по подсказкам должности, избегая ранее показанных вопросов, и при необходимости добавляет кандидатов для покрытия четырёх качеств. ИИ получает должность, ответы анкеты аватара, рабочие темы и пары качеств этого списка. Ответ модели содержит только десять ID. Сервер сверяет ID с базой и берёт оттуда неизменные тексты, варианты и баллы. Последние пять открытых вопросов создаются отдельно, по одному после каждого ответа.

Банк — это набор заранее подготовленных вопросов: рабочая ситуация, вопрос, четыре варианта ответа, баллы, качества и подходящие должности. Исходники хранятся в репозитории, а рабочая копия для подбора теста — в таблице SQLite `question_bank`.

При **каждом запуске API-сервера** `openDatabase()` сверяет рабочую таблицу с полным содержимым поставляемых исходников. Сейчас это **300 готовых ситуаций**: 15 исходных и 285 новых по 12 строительным должностным группам. Проверяются ID, версия, должности, тексты, варианты и баллы; совпадение версии не отменяет проверку содержимого.

- Новый ID добавляется с `active = 1`.
- Изменённая запись обновляется по ID, даже если `version` осталась прежней.
- ID, исчезнувший из исходников, остаётся в SQLite с `active = 0` и не участвует в подборе новых тестов.
- Вернувшийся в исходники ID снова становится активным.
- Повторный запуск с теми же данными ничего не переписывает и не создаёт дубликатов.

Вся синхронизация выполняется одной транзакцией. Некорректный файл или повторяющийся ID останавливает запуск до изменения банка; ошибка записи откатывает всю транзакцию. Аккаунты, ответы и результаты не изменяются. Уже созданные попытки продолжают использовать сохранённые снимки вопросов, включая удалённые из текущего банка. Если до перезапуска сохранился только промежуточный список ID без снимка попытки и в нём есть удалённые вопросы, сервер заново подбирает десятку из активного банка.

| Направление | Должности | Вопросов |
|---|---|---:|
| Строительная площадка | Прораб, мастер монолитных работ, мастер отделочных работ | 72 |
| Контроль качества | Инженер строительного контроля, инженер лаборатории | 47 |
| Инженерная подготовка | Инженер ПТО, BIM-координатор, геодезист, инженер инженерных систем | 94 |
| Организация работ | Инженер ОТ, снабженец, планировщик | 72 |

Ещё 15 исходных общестроительных ситуаций доступны для подбора по подсказкам должности. Они формируются из `src/content/questions.ts`, подсказки должностей и версия задаются в `server/question-bank.ts`. Остальные вопросы хранятся в `server/bank/field.json`, `server/bank/engineering.json` и `server/bank/operations.json`.

## Обновление на сервере

Измените исходники банка и доставьте их вместе с кодом приложения. При следующем старте сервера синхронизация выполняется до начала приёма запросов. При Docker-деплое нужен rebuild/redeploy образа: JSON-файлы включены в `COPY server ./server/`, а исходный набор — в `COPY src/content/questions.ts`. Простой restart старого образа сверяет базу с его прежними файлами.

Используется та же база, что и для аккаунтов и тестов: путь из `DATABASE_PATH`, по умолчанию `data/academy.sqlite`; в контейнере `/app/data/academy.sqlite`. В `compose.yaml` каталог `/app/data` подключён к постоянному тому `academy-data`; в Coolify для него также требуется persistent storage. Загружать локальный файл SQLite поверх серверного для обновления вопросов не нужно.

## Загрузка

Подготовьте UTF-8 JSON-файл с массивом записей и выполните:

```sh
DATABASE_PATH=./data/academy.sqlite node scripts/import-question-bank.mjs ./my-questions.json
```

В PowerShell путь к базе можно задать через `$env:DATABASE_PATH = '.\data\academy.sqlite'`, затем выполнить команду `node scripts/import-question-bank.mjs .\my-questions.json`. Если переменная не задана, используется обычная база `data/academy.sqlite`. Импорт проверяет все записи до записи в базу и сохраняет их одной транзакцией. Повторный импорт ID обновляет вопрос; ранее начатые попытки сохраняют свой снимок вопроса. Новым версиям набора задавайте новое значение `version`, чтобы сравнение результатов не смешивало разные варианты методики.

Импорт — временное изменение рабочей таблицы. При следующем запуске сервера исходники снова определяют её содержимое: внесите новые записи также в один из JSON-файлов `server/bank`, иначе они будут деактивированы. Ручные правки существующих записей в SQLite будут заменены содержимым файлов. Сам импорт открывает базу через `openDatabase()` и поэтому сначала выполняет обычную сверку с исходниками.

Пример одной записи:

```json
{
  "id": "FOREMAN_001",
  "version": "construction-v2",
  "roles": ["прораб", "мастер участка", "монолит"],
  "question": {
    "id": "FOREMAN_001",
    "context": "На участке обнаружено расхождение между актуальным чертежом и заявкой на материал.",
    "text": "Как вы организуете проверку до начала работ?",
    "primaryTrait": "criticalThinking",
    "secondaryTrait": "discipline",
    "options": [
      { "id": "A", "text": "Сверю ревизии документов и зафиксирую расхождение до решения.", "primary": 3, "secondary": 1 },
      { "id": "B", "text": "Остановлю выдачу материала и оформлю запрос по процедуре.", "primary": 1, "secondary": 3 },
      { "id": "C", "text": "Сверю документы и оформлю запрос ответственным до работ.", "primary": 2, "secondary": 2 },
      { "id": "D", "text": "Передам вопрос ответственному и дождусь подтверждённой ревизии.", "primary": 1, "secondary": 2 }
    ]
  }
}
```

Файл должен содержать массив таких объектов (`[{...}, {...}]`). `id` вопроса уникален во всём банке, а четыре `options[].id` уникальны внутри вопроса. Допустимые качества: `criticalThinking`, `confidence`, `discipline`, `engagement`. Первое и второе качество должны различаться. Баллы каждого варианта — целые числа от 0 до 4; хотя бы один вариант должен давать положительный балл каждому из двух качеств. `roles` служит подсказкой для ИИ; текст вопроса и вариантов сотрудники увидят точно в том виде, в каком он записан. Для качественного отбора варианты должны быть сопоставимы по длине и безопасны с точки зрения технологии и охраны труда; автоматическая проверка структуры не заменяет профессиональную экспертизу.

В итоговую попытку попадает ровно 10 разных вопросов, и каждое из четырёх качеств должно встречаться хотя бы в трёх вопросах. Поэтому для узкой должности в банке должны быть темы, которые совместно покрывают всю рубрику. Для постоянного отключения удалите запись из исходников и перезапустите сервер с обновлёнными файлами. Ручное `active = 0` в SQLite действует только до следующей сверки: если ID остаётся в исходниках, он снова станет активным.
