# BI Academy — шпаргалка по архитектуре для защиты

## 1. Коротко о проекте

BI Academy — веб-приложение для оценки рабочих подходов сотрудника строительной компании.
Сотрудник проходит тест: **10 ситуаций из банка 300 вопросов + 5 открытых вопросов**. ИИ подбирает вопросы и оценивает ответы по рубрике, а итоговые проценты считает наш сервер.

**Архитектура:** монолит из трёх частей — React-клиент, сервер на Express и база SQLite. OpenAI подключён как внешний сервис.

```
Браузер (React)
   │  запросы /api/...
   ▼
Сервер (Node.js + Express) ──► OpenAI (ответ строго по JSON-схеме)
   │
   ▼
База SQLite (один файл)
```

В продакшене это один процесс в одном Docker-контейнере: Express отдаёт и API, и собранный фронтенд.

## 4. Слои архитектуры

| Слой | За что отвечает |
|---|---|
| **Клиент (React)** | Показывает данные и собирает ответы. Ничего не считает |
| **Middleware (Express)** | Защищает: проверка источника запроса, лимиты размера и частоты |
| **Авторизация (`requireRole`)** | Определяет пользователя по сессии и проверяет роль |
| **Роуты** | Проверяют права на конкретные данные и управляют сценарием |
| **Модуль ИИ (`dynamic-ai.ts`)** | Общается с OpenAI. Остальной код не знает деталей модели |
| **Доменная логика (`src/domain`, `src/dynamic/domain.ts`)** | Чистые функции: расчёт процентов и валидация. Общие для клиента и сервера |
| **База (SQLite)** | Хранит пользователей, попытки, результаты |

**Главный принцип:** каждый слой отвечает за одно. Права проверяет сервер, проценты считает наш код, ИИ только оценивает по рубрике.

## 5. Путь одного запроса: «Завершить тест»

```
Браузер (React)
   │  POST /api/dynamic/attempts/:id/evaluate
   ▼
Middleware          → проверка источника, лимиты
   ▼
requireRole         → кто пользователь, какая роль
   ▼
Роут                → загрузка попытки, проверка владельца
   ▼
dynamic-ai.ts       → запрос в OpenAI со строгой JSON-схемой
   ▼
Доменная логика     → проверка цитат, расчёт процентов
   ▼
SQLite              → сохранение результата
   ▼
Браузер             → показывает результат
```

1. **Клиент** отправляет запрос на сервер.
2. **Middleware** проверяет, что запрос пришёл с нашего сайта, и ограничивает размер и частоту запросов.
3. **`requireRole`** находит сессию по cookie и проверяет роль.
4. **Роут** берёт попытку из базы и проверяет, что она принадлежит этому пользователю.
5. **Модуль ИИ** отправляет 15 ответов в OpenAI. Модель обязана вернуть JSON строго по схеме: уровни 0–4 и дословные цитаты.
6. **Доменная логика** сверяет цитаты с реальными ответами и сама считает проценты.
7. **База** сохраняет результат, клиент получает готовый ответ.

Если OpenAI не ответил, черновик попытки уже сохранён и запрос можно повторить без потери прогресса.

## 6. Как считаются баллы

- Итог по качеству: **2/3** — выбор в 10 ситуациях, **1/3** — оценка пяти письменных ответов.
- Профессиональные критерии оцениваются по шкале 0–4.
- Если в ответе есть опасное действие, профессиональный балл ограничивается **25%**.
- Формулы лежат в `src/dynamic/domain.ts`. Проценты считает сервер, а не ИИ.

## 7. Безопасность

- Пароли хранятся как scrypt-хеши.
- Сессия — случайный токен в HttpOnly-cookie, в базе лежит только его хеш.
- Права проверяет сервер: сотрудник и руководитель видят только свои данные.
- Защита от CSRF: изменяющий запрос требует специальный заголовок и проверку источника.
- Ограничение частоты запросов на вход, регистрацию и вызовы ИИ.
- Руководитель видит результаты только с согласия сотрудника.
- Ключ OpenAI хранится только на сервере, ответы сотрудников не пишутся в логи.
- Docker-контейнер работает не от root, с файловой системой только для чтения.

## 8. Почему так сделано

| Решение | Почему |
|---|---|
| ИИ выбирает ID вопросов, а не пишет их | Вопросы проверены заранее, попытки можно сравнивать |
| Проценты считает код, а не ИИ | Результат объясним, модель нельзя «уговорить» на высокий балл |
| Монолит | Одна команда, одна инсталляция, простой деплой |
| SQLite | Не нужен отдельный сервер базы, есть транзакции и внешние ключи |
| Общая доменная логика | Одни и те же функции на клиенте и сервере, легко тестировать |
| Минимум зависимостей | Меньше уязвимостей и обновлений |

## 9. Частые вопросы

**Почему SQLite, а не PostgreSQL?**
Для одной инсталляции этого достаточно. При росте меняется только слой базы (`server/database.ts`).

**Что будет, если OpenAI недоступен?**
Черновик сохранён на сервере, сотрудник повторяет запрос и продолжает с того же места.

**Можно ли доверять оценке ИИ?**
ИИ ставит уровни по рубрике и обязан привести цитату. Сервер проверяет цитаты и сам считает проценты.

**Как проверено качество?**
~70 тестовых файлов. В CI три этапа: проверки и unit-тесты, браузерные тесты, тесты Docker-контейнера. Есть реальные прогоны на OpenAI в `docs/реальные проверки/`.

**Что бы вы улучшили?**
Перешли бы на PostgreSQL при росте, вынесли бы лимиты запросов в Redis для нескольких серверов, сделали бы модуль ИИ независимым от провайдера и добавили бы мониторинг.
